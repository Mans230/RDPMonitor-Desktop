From desktop to guest

Add a machine.
Keep watch.

Normal direct setup needs no relay configuration or return pairing code. Your desktop prepares a private command for a fresh Windows VM.

  1. 1

    Open the desktop.

    Extract the Windows ZIP on your watcher PC. Run client\rdpmonitor.exe and keep its adjacent runtime files.

  2. 2

    Prepare your machine.

    Choose Add machine. Enter its name, optional group and reachable address, then prepare the command and accept the preview notice.

  3. 3

    Approve on the VM.

    Paste the private line into an existing Administrator CMD on a fresh VM. The guest-only package installs there—not another desktop app.

  4. 4

    Return to your workspace.

    Leave Add machine open for certificate verification and automatic viewer enrollment. Ordinary connections require authenticated TLS.

Reachability still matters. Direct HTTPS uses TCP 8443 by default. Windows setup restricts its rule to one watcher source; your provider firewall or router must also allow that source and port. Multiple RDP peers may require the advanced source-IP field. Read the installation guide ↗

A few useful details

Before you
get started.

Full deployment guide ↗
Is this a web dashboard?

No. The product is a native Flutter desktop application with a resident Windows guest agent. This website introduces the tool and links to its source and releases; it does not connect to or control your machines.

Do I need a relay server?

Not for normal direct setup when the watcher can reach the VM’s HTTPS endpoint. An optional self-hosted relay exists for advanced routing, but needs its own deployment and valid HTTPS. The installer cannot configure provider accounts or make an unreachable VM reachable.

Can someone claim my machine using its IP?

Knowing the IP alone does not authorize a device. Local Administrator approval binds an exact desktop certificate request; normal connections verify the VM’s CA, hostname and individual client certificate. Protect the private setup command and keep the watcher source restriction narrow.

What does monitoring-only mean?

The unsigned preview forces read-only services and viewer enrollment. It cannot enable administration, protection changes, schedules or automatic RDP/account changes. Wider source capabilities require an appropriately authenticated deployment, authorization and, where applicable, confirmation.

Does closing the desktop stop the agent?

Closing the client and stopping installed guest services are separate actions. Properly installed services run independently of the desktop. The current preview’s full installed lifecycle still requires acceptance on a disposable VM.
